# NEXO - Secure End-to-End Encrypted Messenger

NEXO - это современный мобильный мессенджер с поддержкой сквозного шифрования (E2EE), разработанный на React Native с использованием Expo и Supabase.

## Возможности

- ✅ Регистрация и аутентификация пользователей
- ✅ Личные переписки между пользователями
- ✅ Групповые чаты
- ✅ End-to-End Encryption (E2EE) для всех сообщений
- ✅ Отправка медиафайлов (фото, видео, документы)
- ✅ Голосовые сообщения
- ✅ Реакции на сообщения
- ✅ Тёмная и светлая тема
- ✅ Поиск пользователей
- ✅ Блокировка пользователей
- ✅ Индикатор онлайн статуса
- ✅ Push-уведомления (подготовка)
- ✅ Поддержка Android и iOS

## Технологический стек

- **Frontend**: React Native, Expo, TypeScript
- **Navigation**: Expo Router
- **Backend**: Supabase (PostgreSQL)
- **Authentication**: Supabase Auth
- **Database**: PostgreSQL (Supabase)
- **File Storage**: Supabase Storage
- **Encryption**: TweetNaCl.js, Sodium
- **Real-time**: Supabase Realtime
- **Push Notifications**: Expo Push Notifications

## Установка

### Требования

- Node.js 16+
- npm или yarn
- Git
- Supabase аккаунт

### Шаг 1: Клонируем репозиторий

```bash
git clone https://github.com/kurbanbesleneev21-cloud/suma.git
cd suma
```

### Шаг 2: Устанавливаем зависимости

```bash
npm install
```

### Шаг 3: Настраиваем Supabase

1. Создайте проект на [supabase.com](https://supabase.com)
2. Перейдите в SQL Editor
3. Выполните все SQL запросы из файла `SQL_SETUP.md`
4. Скопируйте ваш `Project URL` и `Anon Key` из Settings → API

### Шаг 4: Создаём файл .env.local

```bash
cp .env.example .env.local
```

Отредактируйте `.env.local` и добавьте ваши Supabase credentials:

```
EXPO_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=YOUR_ANON_KEY_HERE
```

### Шаг 5: Запускаем приложение

#### Для Android:

```bash
npm run android
```

#### Для iOS:

```bash
npm run ios
```

#### Для Web:

```bash
npm run web
```

## Security и E2EE

### Как работает шифрование

1. **Генерация ключей**: При регистрации для каждого пользователя генерируется пара асимметричных ключей (публичный и приватный)
2. **Отправка сообщений**: Сообщение шифруется на устройстве отправителя с использованием публичного ключа получателя
3. **Хранение**: На сервере хранятся только зашифрованные сообщения
4. **Получение**: Получатель расшифровывает сообщение своим приватным ключом
5. **Файлы**: Файлы шифруются симметричным ключом, который затем передаётся получателю в зашифрованном виде

### Защита данных

- ✅ Row Level Security (RLS) в Supabase
- ✅ Приватные ключи не отправляются на сервер
- ✅ Все критичные операции проверяются на серверной стороне
- ✅ Файлы хранятся в приватном хранилище

## Особенности реализации

### Регистрация и Авторизация

- Используется Supabase Auth для безопасной работы с паролями
- Email подтверждение (опционально)
- Восстановление пароля через email
- Сессии автоматически сохраняются на устройстве

### Личные переписки

- Один-на-один чаты между пользователями
- Все сообщения зашифрованы E2EE
- Автоматическое создание приватного чата при первом сообщении
- Индикатор онлайн статуса

### Групповые чаты

- Создание групп с управлением участниками
- Различные роли (администратор, участник)
- Групповые ключи шифрования (каждый участник имеет свой зашифрованный ключ)
- При удалении участника - ротация ключей

### Медиафайлы

- Загрузка фотографий, видео, документов
- Все файлы шифруются перед загрузкой на сервер
- Приватное хранилище Supabase

### Уведомления

- Готовность к интеграции Expo Push Notifications
- Настройка на уровне пользователя

## API Endpoints (Supabase)

Все операции выполняются через:
- `supabase.from('table_name')` для работы с базой данных
- `supabase.auth.*` для аутентификации
- `supabase.storage.from('bucket')` для работы с файлами

## Тестирование

### Тестовые аккаунты

После развёртывания вы можете создать несколько тестовых аккаунтов для проверки функциональности:

1. Создайте первый аккаунт: `user1@example.com` / `password123`
2. Создайте второй аккаунт: `user2@example.com` / `password123`
3. Авторизуйтесь в первом аккаунте
4. Найдите второго пользователя через Контакты
5. Отправьте сообщение - оно автоматически зашифруется и отправится

### Проверка E2EE

1. Отправьте сообщение первому пользователю
2. Проверьте Supabase Dashboard - в таблице `messages` поле `encrypted_content` должно содержать зашифрованные данные
3. Поле `content` должно быть пустым
4. Получатель должен видеть расшифрованное сообщение

## Troubleshooting

### Проблема: "Cannot find module '@supabase/supabase-js'"

**Решение**: Переустановите зависимости
```bash
npm install
```

### Проблема: "EXPO_PUBLIC_SUPABASE_URL is not set"

**Решение**: Создайте файл `.env.local` с вашими Supabase credentials

### Проблема: "Permission denied" при работе с файлами

**Решение**: Проверьте разрешения приложения в настройках операционной системы
